# Dashboard requirements over Research State v0.1

The Dashboard is not implemented in this round. It must be a read/write view
over validated Research State, never an independent source of truth.

## Overview

Show:

- Project lifecycle status and current phase;
- current epistemic verdict (`GO`, `RESTRICTED_GO`, or `KILL`);
- current operational decision (`FREEZE`, `RESUME`, `BLOCK`, etc.);
- active hypothesis branches and killed branches;
- blockers with source/target/type;
- highest-priority next action;
- most recent AgentRuns;
- last Checkpoint and resume point.

FROZEN and KILLED must have distinct visual and semantic treatment.

## Research Graph

Render linked Hypotheses, Claims, Evidence, Theorems, Decisions, Dependencies,
Experiments, Papers, Tasks, and Artifacts. Required interactions:

- filter by object type/status;
- expand support/opposition edges;
- show branch-local KILL without coloring the whole Project KILLED;
- show broken or blocked dependency paths;
- open source Artifact and provenance details.

## Literature

Show:

- paper clusters;
- reading priority;
- collision risk and exact overlap;
- MUST READ and NOVELTY THREAT queues;
- verified versus unverified metadata;
- Claims citing each Paper;
- last checked time and source links.

## Theory

Show:

- theorem/Lemma dependency DAG;
- theorem status and assumptions;
- proof AgentRuns and counterexample AgentRuns separately;
- known gaps and blockers;
- human verification independent of agent proof status;
- cited Papers and supporting Claims.

The UI must never label `PROVED_BY_AGENT` as “verified.”

## Experiments

Show:

- planned, running, passed, failed, inconclusive, and aborted experiments;
- exact config, dataset, code reference, seed, and environment;
- metrics and raw/processed result Artifacts;
- compute, runtime, tokens, and cost where recorded;
- interpretation and failure reason;
- reproducibility flag and result Evidence.

## Agent Runs

Show:

- role, model, task, prompt reference, start/finish/duration;
- inputs, outputs, Artifacts, errors;
- claims created/modified;
- decisions proposed;
- compute, tokens, and cost;
- unknown legacy fields as unknown, never zero.

## Evidence / Provenance

Clicking a Claim must show:

- supporting Evidence;
- opposing Evidence;
- source Papers, Theorems, Experiments, and Artifacts;
- authoring AgentRuns/human sources;
- strength, uncertainty, and verification state;
- dependent blockers;
- Decisions that relied on the Claim/Evidence.

Evidence polarity must be visible; the Dashboard must not hide negative results.

## Portfolio

Across projects, show:

- lifecycle buckets: IDEA, AUDITING, RUNNING, BLOCKED, FROZEN, PAPER_WRITING,
  SUBMITTED, ACCEPTED, REJECTED, KILLED, ARCHIVED;
- research verdicts: GO, RESTRICTED_GO, KILL, UNKNOWN;
- priority and next action;
- estimated cost and expected information gain;
- optional publishability metadata if later added;
- unresolved blockers and stale checkpoints.

The initial portfolio index may be generated by scanning validated YAML/JSON
files. A later SQLite read model may accelerate this without becoming canonical.

## Dashboard mutation contract

Future UI actions must map to explicit state operations:

- changing status appends a Decision;
- freezing creates a Checkpoint with resume instructions;
- verifying a theorem updates verification only after named human action;
- adding evidence creates a new Evidence object;
- editing an Artifact creates a new version/hash;
- deleting historical Decisions, Evidence, AgentRuns, or Checkpoints is
  disallowed through normal UI.

## Minimum API/read model

The v0.1 state already supports endpoints or selectors for:

- project summary;
- active hypothesis tree;
- decision history;
- blocker list;
- next-action queue;
- literature threat table;
- theorem/Lemma graph;
- experiments and AgentRuns;
- claim provenance;
- artifact registry;
- portfolio aggregation.

No visual design, frontend framework, authentication, collaboration backend, or
database server is specified here.
